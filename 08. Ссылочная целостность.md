# Решение задач SQL — Ссылочная целостность

## 1. Создание таблиц Клиент и Заказ со связью 1:N

Включаем проверку внешних ключей:

```sql
PRAGMA foreign_keys = ON;
```

Создаём таблицу клиентов:

```sql
CREATE TABLE client (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL
);
```

Создаём таблицу заказов:

```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    client_id INTEGER NOT NULL,
    amount REAL,
    FOREIGN KEY (client_id) REFERENCES client(id)
);
```

Добавляем двух клиентов:

```sql
INSERT INTO client (name)
VALUES
    ('Иванов'),
    ('Петров');
```

Добавляем три заказа:

```sql
INSERT INTO orders (client_id, amount)
VALUES
    (1, 100),
    (1, 200),
    (2, 150);
```

Связь 1:N означает, что один клиент может иметь несколько заказов.

## 2. Добавление ON DELETE CASCADE

Создадим таблицу заказов с каскадным удалением.

```sql
CREATE TABLE orders_cascade (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    client_id INTEGER NOT NULL,
    amount REAL,
    FOREIGN KEY (client_id)
        REFERENCES client(id)
        ON DELETE CASCADE
);
```

Добавляем заказы:

```sql
INSERT INTO orders_cascade (client_id, amount)
VALUES
    (1, 100),
    (1, 200),
    (2, 150);
```

При удалении клиента все его заказы удаляются автоматически.

## 3. Попытка вставить заказ с несуществующим клиентом

Проверяем работу внешнего ключа:

```sql
INSERT INTO orders_cascade (client_id, amount)
VALUES (99, 500);
```

**Результат:** SQLite выдаст ошибку:

```text
FOREIGN KEY constraint failed
```

Причина: клиента с ID 99 не существует в таблице client.

## 4. Удаление клиента и проверка заказов

Удаляем клиента с ID 1:

```sql
DELETE FROM client
WHERE id = 1;
```

Проверяем таблицу клиентов:

```sql
SELECT * FROM client;
```

Проверяем таблицу заказов:

```sql
SELECT * FROM orders_cascade;
```

**Результат:** клиент с ID 1 удалён, но заказы в `orders_cascade` останутся, поскольку в таблице `orders_cascade` были добавлены отдельные записи, связанные с таблицей `client`, и при включённом CASCADE они тоже удалятся.

## 5. Изменение поведения на ON DELETE RESTRICT

Создаём таблицу заказов с ограничением RESTRICT.

```sql
CREATE TABLE orders_restrict (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    client_id INTEGER NOT NULL,
    amount REAL,
    FOREIGN KEY (client_id)
        REFERENCES client(id)
        ON DELETE RESTRICT
);
```

Добавляем клиента:

```sql
INSERT INTO client (name)
VALUES ('Сидоров');
```

Добавляем его заказ:

```sql
INSERT INTO orders_restrict (client_id, amount)
VALUES (3, 300);
```

Пытаемся удалить клиента:

```sql
DELETE FROM client
WHERE id = 3;
```

**Результат:** SQLite выдаст ошибку:

```text
FOREIGN KEY constraint failed
```

Причина: нельзя удалить клиента, пока в таблице заказов существуют связанные с ним записи.

## 6. Создание таблицы Товар с FK на Категория и ON DELETE SET NULL

Создаём таблицу категорий:

```sql
CREATE TABLE category (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL
);
```

Добавляем категории:

```sql
INSERT INTO category (name)
VALUES
    ('Электроника'),
    ('Книги');
```

Создаём таблицу товаров:

```sql
CREATE TABLE product (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    price REAL,
    category_id INTEGER,
    FOREIGN KEY (category_id)
        REFERENCES category(id)
        ON DELETE SET NULL
);
```

Добавляем товары:

```sql
INSERT INTO product (name, price, category_id)
VALUES
    ('Наушники', 3500, 1),
    ('Книга SQL', 1200, 2);
```

Удаляем категорию с ID 1:

```sql
DELETE FROM category
WHERE id = 1;
```

Проверяем результат:

```sql
SELECT * FROM product;
```

**Результат:** товар «Наушники» останется в таблице, но его `category_id` станет NULL.

## 7. Создание связи M:N через промежуточную таблицу

Создаём таблицу заказов:

```sql
CREATE TABLE orders_mn (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    order_date TEXT DEFAULT CURRENT_DATE
);
```

Создаём таблицу товаров:

```sql
CREATE TABLE products_mn (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    price REAL
);
```

Добавляем заказы:

```sql
INSERT INTO orders_mn (order_date)
VALUES
    ('2026-10-30'),
    ('2026-10-31');
```

Добавляем товары:

```sql
INSERT INTO products_mn (name, price)
VALUES
    ('Телефон', 25000),
    ('Ноутбук', 55000);
```

Создаём промежуточную таблицу:

```sql
CREATE TABLE order_product (
    order_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL,

    FOREIGN KEY (order_id)
        REFERENCES orders_mn(id),

    FOREIGN KEY (product_id)
        REFERENCES products_mn(id)
);
```

Добавляем связи между заказами и товарами:

```sql
INSERT INTO order_product (order_id, product_id, quantity)
VALUES
    (1, 1, 2),
    (1, 2, 1),
    (2, 1, 1);
```

Проверяем результат:

```sql
SELECT * FROM order_product;
```

## 8. Создание таблицы с составным PRIMARY KEY

Создаём таблицу `order_item`, в которой составной первичный ключ состоит из двух столбцов: `order_id` и `product_id`.

```sql
CREATE TABLE order_item (
    order_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL,

    PRIMARY KEY (order_id, product_id),

    FOREIGN KEY (order_id)
        REFERENCES orders_mn(id),

    FOREIGN KEY (product_id)
        REFERENCES products_mn(id)
);
```

Добавляем две записи:

```sql
INSERT INTO order_item (order_id, product_id, quantity)
VALUES
    (1, 1, 2),
    (1, 2, 1);
```

Проверяем составной PRIMARY KEY:

```sql
INSERT INTO order_item (order_id, product_id, quantity)
VALUES (1, 1, 5);
```

**Результат:** SQLite выдаст ошибку:

```text
UNIQUE constraint failed
```

Причина: комбинация `order_id = 1` и `product_id = 1` уже существует.

## 9. Задача со звёздочкой — самоссылочная таблица Сотрудник

Создаём таблицу сотрудников, в которой `manager_id` ссылается на `id` этой же таблицы.

```sql
CREATE TABLE employee (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    manager_id INTEGER,
    FOREIGN KEY (manager_id)
        REFERENCES employee(id)
);
```

Добавляем сотрудников:

```sql
INSERT INTO employee (name, manager_id)
VALUES
    ('Директор', NULL),
    ('Менеджер', 1),
    ('Разработчик', 2),
    ('Дизайнер', 2);
```

Проверяем данные:

```sql
SELECT * FROM employee;
```

**Объяснение:**

Самоссылочная таблица нужна для хранения иерархии сотрудников.

- Директор не имеет руководителя, поэтому `manager_id = NULL`.
- Менеджер подчиняется директору.
- Разработчик и дизайнер подчиняются менеджеру.

## 10. Задача на поиск ошибки

Дан код:

```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY,
    client_id INTEGER REFERENCES client(id) ON DELETE CASCADE
);

PRAGMA foreign_keys = OFF;

INSERT INTO orders (id, client_id)
VALUES (1, 999);
```

**Вопрос:** почему вставка пройдёт, хотя клиента с ID 999 нет?

**Ответ:**

В SQLite проверка внешних ключей по умолчанию отключена или может быть отключена командой:

```sql
PRAGMA foreign_keys = OFF;
```

Поэтому SQLite не проверяет существование клиента с ID 999 и разрешает вставку записи.

Чтобы исправить ситуацию, необходимо включить проверку:

```sql
PRAGMA foreign_keys = ON;
```

После включения проверки вставка заказа с несуществующим клиентом будет запрещена.

## 11. Задача на предсказание результата

Выполняется запрос:

```sql
DELETE FROM client
WHERE id = 1;
```

При условии, что используется `ON DELETE CASCADE`.

**Ответ:**

1. Клиент с ID 1 будет удалён.
2. Заказ с ID 1 будет удалён автоматически.
3. Заказ с ID 2 также будет удалён автоматически.
4. Клиент с ID 2 останется в таблице.

Итог: клиент и все его связанные заказы будут удалены благодаря каскадному удалению.

## Заключение

В ходе выполнения работы были изучены:

- PRIMARY KEY — первичный ключ.
- FOREIGN KEY — внешний ключ.
- ON DELETE CASCADE — каскадное удаление.
- ON DELETE RESTRICT — запрет удаления родителя при наличии дочерних записей.
- ON DELETE SET NULL — установка NULL при удалении родителя.
- Связь 1:N — один ко многим.
- Связь M:N — многие ко многим.
- Составной PRIMARY KEY — первичный ключ из нескольких столбцов.
- Самоссылочные таблицы — таблицы со ссылкой на самих себя.
- PRAGMA foreign_keys — включение и проверка внешних ключей.

**Результат:** все задания по теме «Ссылочная целостность» выполнены на SQLite.
